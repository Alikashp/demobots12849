# Журнал изменений

## 08.10.2026 — Ф5: запуск на Railway

- **Что изменено.** Добавлен `.python-version` (3.12): по нему сборщик Railway выбирает
  версию Python, зависимости — из `requirements.txt`. Файлов `railway.toml`,
  `railway.json` и каталога `.railway/` нет: Config as Code у Railway устарел и новыми
  сервисами не читается, поэтому команда запуска задаётся в настройках сервиса.
  Проверки при запуске (`saqal/startup.py`): на Railway бот не стартует без тома или с
  `DB_PATH` вне тома и пишет причину в лог; каталог для базы создаётся сам; доступность
  чата администратора проверяется при старте, а при недоступности в лог уходит понятная
  ошибка и бот работает дальше. В README — раздел «Запуск на Railway» по шагам. В
  docs/02-architecture-plan.md добавлены критерии Ф5.
- **Требования.** А1, А2, А8, Д7, В1; критерии 5.1–5.6.
- **Как проверено.** `ruff check`, `ruff format --check` и `pytest` зелёные. Новые тесты —
  только на 5.2–5.4 (`tests/test_startup.py`).
- **Что не сделано.** Деплой на Railway вживую не выполнялся, и бот вживую в Telegram
  тоже не проверялся. Названия кнопок и разделов панели Railway в README написаны
  без сверки с документацией: docs.railway.com из среды разработки недоступна. Не
  проверено, что сборщик Railway берёт зависимости из `requirements.txt`, а не из
  `pyproject.toml`, когда в репозитории есть оба файла.

## 07.10.2026 — Ф4: команды владельца; требования, редакция 3

- **Что изменено.** Требования переведены в редакцию 3: правки Н5 и В3, добавлены П4, П5, Р8.
  В docs/02-architecture-plan.md добавлены критерии Ф4. Команды `/today` и
  `/broadcast текст` (`saqal/admin.py`) работают только в чате `ADMIN_CHAT_ID` — в группе
  (в том числе `/команда@бот`) или в личном чате владельца. `/today` — записи на сегодня
  по мастерам. `/broadcast` — предпросмотр с числом получателей и кнопками «Отправить» /
  «Отмена», затем рассылка с отчётом «доставлено N из M». Черновик рассылки хранится в базе
  (таблица `broadcasts`) и переводится в «отправляется» ровно один раз, поэтому повторное
  нажатие и кнопки после перезапуска не дают второй рассылки. `/start` теперь запоминает
  пользователя (таблица `users`); получатели — эти пользователи и все клиенты, каждый один раз.
  Тестовое напоминание — Т3, если визит сегодня по Казани, иначе Т2.
- **Требования.** В2–В4, Н5 (ред. 3), П4, П5, Р8; А9, А10; критерии 4.1–4.11.
- **Как проверено.** `ruff check`, `ruff format --check` и `pytest` (184 теста) зелёные.
  Тесты 4.7 подают два нажатия «Отправить» параллельно (10 сдвигов, один и два
  администратора). Тесты ловят ошибки: при намеренно сломанной проверке чата
  администратора, защите черновика, составе получателей, перехвате ошибок отправки,
  выборе Т2/Т3, запоминании `/start` и фильтре отменённых записей они падают.
- **Что не сделано.** Вживую в Telegram не проверялось, в том числе работа в настоящей
  группе с режимом приватности. Разметка (жирный, ссылки) в тексте рассылки не
  сохраняется: клиенты и предпросмотр получают обычный текст. Если бот перезапустился
  посреди рассылки, оставшимся получателям она не уйдёт. Запуск на Railway (Ф5) не начат.

## 07.10.2026 — Ф3: напоминания

- **Что изменено.** Напоминания за 24 часа (Т2) и за 2 часа (Т3) с кнопкой «❌ Отменить
  запись», которая ведёт на то же подтверждение, что и «Мои записи». Напоминания — строки
  таблицы `reminders`, создаются в одной транзакции с записью; прошедшие сроки не создаются.
  Фоновый цикл (`saqal/reminders.py`) раз в 5 секунд в одной транзакции отмечает наступившие
  напоминания (`sent`) и пропускает опоздавшие больше чем на 10 минут и напоминания
  по отменённым записям (`skipped`), затем отправляет каждое отдельной задачей с таймаутом.
  Цикл запускается и останавливается вместе с ботом. Команда `/test_reminder` создаёт
  отдельное тестовое напоминание (Т2) через минуту по ближайшей записи. В
  docs/02-architecture-plan.md добавлены А12 и критерии Ф3.
- **Требования.** Н1–Н5, Т2, Т3, М2, М3; А6, А10, А12; критерии 3.1–3.10.
- **Как проверено.** `ruff check`, `ruff format --check` и `pytest` (130 тестов) зелёные.
  Тесты подменяют часы и `sleep` цикла, настоящих секунд не ждут. Подменённый Telegram
  умеет падать и зависать по выбранным чатам. Тесты ловят ошибки: при намеренно сломанной
  проверке статуса записи, порога опоздания, интервала, отметки до отправки, параллельной
  отправки, создания напоминаний и перехвата ошибок они падают.
- **Что не сделано.** Вживую в Telegram не проверялось. Команды владельца (Ф4), запуск
  на Railway (Ф5) — не начаты. Новые тексты ждут утверждения в PR.

  «Поделиться номером». В docs/02-architecture-plan.md добавлены критерии Ф2.
- **Требования.** К1, М1–М4, Т5, К6, К9; А5, А7, А9; критерии 2.1–2.11.
