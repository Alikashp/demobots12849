# SAQAL — демо-бот записи в барбершоп

Telegram-бот записи клиентов. Требования — [docs/01-requirements.md](docs/01-requirements.md),
архитектура и план — [docs/02-architecture-plan.md](docs/02-architecture-plan.md),
история — [CHANGELOG.md](CHANGELOG.md).

## Запуск локально

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
export BOT_TOKEN=...        # токен от @BotFather
export ADMIN_CHAT_ID=...    # ID чата администратора
export DB_PATH=./saqal.db   # файл SQLite
.venv/bin/python -m saqal
```

Данные барбершопа (мастера, услуги, часы работы) — в [shop.toml](shop.toml).

## Запуск на Railway

Бот работает в одном экземпляре и хранит базу в файле SQLite. На Railway этот файл
должен лежать на томе (volume): без тома база стирается при каждом деплое, и бот в
таком случае сам откажется запускаться.

Понадобятся аккаунты в Telegram, на GitHub (с доступом к этому репозиторию) и на
[railway.com](https://railway.com).

### 1. Создайте бота в BotFather

1. В Telegram откройте [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Введите имя бота (как его увидят клиенты), затем username — он должен
   заканчиваться на `bot`, например `saqal_kazan_bot`.
3. BotFather пришлёт токен вида `1234567890:AA...`. Это `BOT_TOKEN`. Никому его
   не показывайте и не кладите в репозиторий. Если токен утёк — в BotFather
   `/revoke` выдаст новый.

### 2. Узнайте ADMIN_CHAT_ID

Сюда бот присылает уведомления о записях и отменах, здесь работают `/today` и
`/broadcast`. Это может быть группа (удобно, если уведомления читают несколько
человек) или ваш личный чат с ботом. Делайте этот шаг **до** запуска бота на Railway:
запущенный бот сам забирает сообщения, и в шаге 4 вы их не увидите.

- **Группа.** Создайте группу в Telegram и добавьте в неё бота (по его username).
  Отправьте в группу команду `/start@username_бота`.
- **Личный чат.** Откройте своего бота и отправьте ему любое сообщение, например `/start`.

Затем откройте в браузере адрес, подставив свой токен вместо `<BOT_TOKEN>`:

```
https://api.telegram.org/bot<BOT_TOKEN>/getUpdates
```

Найдите в ответе `"chat":{"id":...}` у своего сообщения. Это число и есть
`ADMIN_CHAT_ID`. У группы оно отрицательное (например `-1001234567890`), минус
входит в число. Если ответ пустой (`"result":[]`), отправьте сообщение ещё раз и
обновите страницу.

### 3. Создайте проект на Railway из репозитория

1. На [railway.com](https://railway.com) нажмите **New Project** → **Deploy from GitHub repo**.
   При первом входе Railway попросит доступ к GitHub — разрешите его для этого репозитория.
2. Выберите репозиторий бота. Railway создаст сервис и начнёт первую сборку.
3. Откройте сервис → **Settings** → раздел **Source** и проверьте, что ветка — `main`.
   Railway пересобирает бота при каждом изменении `main`.

Первый деплой упадёт с сообщением «Не заданы переменные окружения» — это нормально,
переменные зададим в шаге 6.

Версия Python (3.12) берётся из файла `.python-version`, зависимости — из
`requirements.txt`. Ничего настраивать для этого не нужно.

### 4. Задайте команду запуска и проверьте политику перезапуска

В сервисе откройте **Settings** → раздел **Deploy**:

1. **Custom Start Command** — впишите `python -m saqal` и сохраните.
2. **Restart Policy** — должно стоять **On Failure** (у Railway это значение по
   умолчанию): если бот упадёт, Railway перезапустит его сам, до 10 раз подряд.
3. Число реплик (**Replicas**) оставьте равным 1. Два экземпляра бота одновременно
   работать не могут: Telegram отдаёт обновления только одному из них, а напоминания
   задублируются.

### 5. Подключите том

1. На схеме проекта нажмите правой кнопкой мыши на сервис бота → **Attach Volume**
   (или **Create** → **Volume** и выберите сервис бота).
2. **Mount path** — впишите `/data`.

Railway сам передаст боту путь тома в переменной `RAILWAY_VOLUME_MOUNT_PATH`.

### 6. Задайте переменные

В сервисе откройте вкладку **Variables** и добавьте три переменные (**New Variable**):

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен из шага 1 |
| `ADMIN_CHAT_ID` | число из шага 2, вместе с минусом, если он есть |
| `DB_PATH` | `/data/saqal.db` — файл базы внутри тома из шага 5 |

После сохранения Railway предложит применить изменения (**Deploy**) — подтвердите.
Бот пересоберётся и запустится.

### 7. Логи и перезапуск

- **Логи.** В сервисе откройте вкладку **Deployments**, нажмите на последний деплой
  и откройте **Deploy Logs** (журнал работы бота) или **Build Logs** (журнал сборки).
- **Признаки, что всё хорошо:** в Deploy Logs есть строки `admin chat ... is reachable`
  и `reminders loop started`. После этого напишите боту `/start` — он ответит приветствием.
- **Перезапуск.** На вкладке **Deployments** откройте меню (⋮) у текущего деплоя и
  выберите **Restart**. **Redeploy** заново собирает бота из того же коммита.

Если бот не запускается, причина написана в последних строках Deploy Logs:

- `Бот не запущен: К сервису на Railway не подключён том…` — выполните шаг 5.
- `Бот не запущен: DB_PATH=… лежит вне тома…` — исправьте `DB_PATH` в шаге 6, путь
  должен начинаться с пути тома (`/data/...`).
- `Не заданы переменные окружения: …` — выполните шаг 6.
- `Чат администратора ADMIN_CHAT_ID=… недоступен боту…` — бот работает и записывает
  клиентов, но уведомления и команды владельца не дойдут. Проверьте число из шага 2 и
  что бот состоит в группе.
